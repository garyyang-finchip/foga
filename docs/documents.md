# The cell's documents (foga cell docs build | publish | status)

One configuration, several documents (design memo, section 2, "One local config, several documents", and section 9, 3d-2): everything a cell says about itself to the outside is generated from `cell.config.json` and the chain, each document carrying only the fields its standard prescribes, the shared metadata beside them in `manifest.json`. The node serves them; `foga cell docs publish` commits what the chain should hold and reads it back.

| File | Standard | What it says | On chain |
|---|---|---|---|
| `registration.json` | ERC-8004 `registration-v1` | name, description, image, the services (MCP `2026-07-28`, A2A `1.0`, web), `registrations` (the agent id and its registry), `x402Support: false`, `active`, `supportedTrust`, an `x-foga` block (cell, anchor, binding, specification) | `setAgentURI(agentId, uri)` on the identity registry |
| `aid-document.json` | ERC-8434 `aid-document/v1` | the identity facet (`aid:core/identity/v1`, digest of the registration), the standing facet when an issuer attested it (`aid:core/kya/v1`), the skills facet (`aid:skills/erc8338/v1`), the endpoints facet when the cell has a public URL (`aid:endpoints/v1`) | `setDocumentURI(uri, digest)` on the AID registry; digest = keccak256 of the JCS form |
| `ard-agent.json` | ERC-8444 agent descriptor | the descriptor the birth registered, with the offered skills among the capabilities (`erc8338:<name>`) and the registration | `updateDescriptor(recordId, …)` on the cell's record |
| `auf-unit.json` | ERC-8454 unit definition | the cell's economic boundary (agent element, treasury position, the ports) | `publishVersion(unitId, boundaryHash, uri, [])`: a new version when the boundary changed |
| `agent-card.json` | A2A 1.0 AgentCard | the JSON-RPC interface at the A2A URL, the offered skills by name and version, the credential schemes, no streaming or push | not on chain; served at `/.well-known/agent-card.json` (docs/a2a.md) |
| `server.json` | MCP registry manifest (2025-12-11) | the package's manifest with this cell's MCP URL as the remote | not on chain; what `mcp-publisher` publishes for the OG instance |
| `manifest.json` | `foga.documents/1` | cell, account, agent id, chain, version, built time, public URL, and per file its content hash (keccak256 of the JCS form) and size | — |

## Where and how

`foga cell docs build --config <cfg>` writes them under `runtime.http.documentsDir` (`documents`, relative to the configuration's directory). The version counts up when any content hash changed since the last build; an unchanged build keeps its version. The node serves the directory as built: `GET /documents/<file>` for each file and the manifest, `GET /.well-known/agent-card.json` (the card) and `GET /.well-known/agent-registration.json` (the registration, where ERC-8004 domain verification looks); nothing else under those paths, and `not published yet` until a build exists.

The URI a commitment carries depends on `runtime.http.publicUrl`: with one, the registration is committed as `<publicUrl>/.well-known/agent-registration.json` and the AID document as `<publicUrl>/documents/aid-document.json`; without one, each is committed as a `data:` URI holding the document itself, so a cell with no public face is still complete on chain. The ARD descriptor and the unit definition are always committed as `data:` URIs (the publication form their standards use). The endpoints in the registration and the card are `presence.endpoints` when set, otherwise derived from the public URL (`/mcp`, `/a2a`, the URL itself); `presence.provider` names the organization behind the card.

`foga cell docs publish --config <cfg> [--wallet <dir>]` builds, then runs the capability `docs_publish` with the operator key: one keyed job (its id derived from the documents' hashes and the URI base, so the same documents are the same job and nothing is sent twice) whose steps are only the commitments that differ from what the chain holds — a document already on chain as built is skipped, and a unit whose boundary did not change gets no new version. Each step is the operator's own call through the account (`setAgentURI`, `setDocumentURI`, `updateDescriptor`, `publishVersion` are in the `identity` scope group; a cell born before `publishVersion` joined it needs the owner's `setOperatorAllowedBatch`, and `foga node preflight` says so). Afterwards every commitment is read back from the chain and compared with what was built — the registration fetched from its URL and hashed against the AID identity facet's digest, the document URI's digest, the descriptor hash, the latest unit version's boundary hash — and a mismatch is a failed publish (exit 2), as the memo's v0.2 asks. `foga cell docs status` prints the same comparison without committing anything, and `docs_status` is the public read of it over MCP and HTTP.

## Over MCP and HTTP

`docs_status` (read, public) and `docs_publish` (act, the operator's view) are catalog capabilities like any other: an MCP client with the operator key, or an HTTP caller whose grant reaches act and operator visibility, publishes with the same checks and records. The capability's own read-back does not fetch URLs (a node answering its own request is not the check wanted); the CLI's does.
