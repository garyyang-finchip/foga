# Changelog

## 0.6.0-alpha.4 — 2026-11-02 (Phase 3c: Loop D)

A model proposes, the catalog decides, and the acceptance reads the records: the runner, two model adapters, the independent demander, the orchestrated unscripted run with its recovery drill, and the doctor's Loop D verdicts beside layer 5. docs/loop-d.md.

- **The runner** (`src/node/runner.ts`, caller `runner`): each tick perceives through the read capabilities (`cell_status`, `tender_list`, `tender_inspect`, the decisions, the journal since the last tick, the budget books) into a `Situation` (`src/node/model/types.ts`; a tender is `open`, `eligible`, `refused`, `submitted`, `settled` or `failed`), hands it with the catalog as tools to the model, carries out the proposals — reads at once, acts through `Catalog.invoke` in act mode with the result or the refusal returned so the model may revise — and records the tick: the decision records carry `model: {provider, model, promptHash, responseHash}`, the journal a `runner-tick` entry with the counts, the decision ids and the hash of the whole transcript. Limits: `runtime.model.maxToolCallsPerTick` (12), `maxActsPerTick` (2; a pre-check does not count), `dailyCalls` per UTC day (counted in the store, shown in `cell_status`); a tick with nothing to decide does not call the model; a model failure is a `runner-model-error` entry. `--transcripts <dir>` writes transcripts locally for debugging; nothing of them enters the store or the evidence.
- **The model adapters** (`src/node/model/`): one interface, `propose(request)`, in the Messages API's vocabulary. `anthropic` over plain `fetch` (`ANTHROPIC_API_KEY`, `runtime.model.model` required, retries on 429/5xx, errors never carry the key, `ANTHROPIC_BASE_URL` for a stand-in). `stub`: a deterministic decision table over the situation and the tick's transcript — inspect, pre-check, run, submit, settle, withdraw, the lowest id first; a refusal is the verdict (a `safety` refusal is retried once the binding is Satisfied); once per cell a tender five times the per-operation cap is proposed on purpose (case g).
- **`foga node run --config <cfg> [--model stub|anthropic] [--listen|--no-http] [--interval] [--once|--ticks n] [--transcripts dir]`**: the embedded node — the HTTP server, the watchers and the runner on the poll interval, the operator key alone.
- **The demander** (`src/demo/demander.ts`; `foga demo demander …`): an independent process with its own key and store minting cases a (probe at a seeded block), b (extract over the fixture by file name), c (a skill the cell lacks), d (reward below the floor), d2 (deadline too close), e (a judged tender with the demander as authority), f (minted during the suspension), in an order the seed decides, each with what the acceptance expects.
- **Loop D orchestrated** (`src/demo/loop-d.ts`; `foga demo --loop-d`, `foga loop-d run --world --rpc`): a new cell with fresh keys funded by the world operator, standing attested, skills minted; the node as a child process (`foga node run`) on a free HTTP port; the first batch worked; the node killed with SIGKILL after its first confirmed submission and before the settlement, then restarted; through HTTP beside the runner the same submission again (`idempotent`, the same transaction), the same job with another request (`conflict`), three mints of 0.0008 ETH at once (two allowed, the third refused at `budget`); the guardian's suspension (a one-shot node with the guardian key writing to the same store), case f refused at `safety`, the resume, f taken; then the evidence `foga.loop-d-evidence/1` (`src/demo/evidence.ts`): the cases with outcomes, the budget probe, the runner's counts and trajectory hashes, the recovery, the entrances, the four budget books, every transaction the operator key signed decoded inside `execute` and checked against `operatorAllowed`, and the store's decisions, jobs, operations and journal. Under a minute on anvil.
- **`foga doctor --loop-d <evidence> [--compare <evidence2>] [--out]`** (`src/doctor/loop-d.ts`): layer `D` beside layer 5 when `--world` is given, the table alone otherwise (`foga.loop-d-report/1`). Rows: every operation under an allowed decision; a refused attempt broadcasts nothing; spend within the four books; operator transactions all at the account and allow-listed; none reverted; the cases a–f as expected; case g; the evidence complete; the recovery; the same request through another entrance; the same job under another request; concurrent acts with distinct nonces; model-agnostic with `--compare`.
- **Two corrections the run exposed.** (1) Three concurrent acts each passed the node's budget gate because none saw the others' reservations, and the account's daily cap refused the third on chain (`execution`): the catalog's decision section (business gates, wallet gate, job creation) now runs one act at a time per node (`Node.serialize`), and a job reserves the value its plan moves from its creation (`jobs.value_wei`; an older store gains the column on open), counted by `budgetBooks` until its operations carry it — the third mint is refused at `budget` before anything is sent. (2) The value an `execute` carries inside was not recorded on the operation's row (the outer transaction's zero was), so the value book undercounted: `markSent` records the binding's value.
- **Store.** `PRAGMA busy_timeout = 5000`: a one-shot command (a guardian's suspension, a key minted) writes while the node runs instead of failing on SQLITE_BUSY.
- **Configuration.** `runtime.model.maxToolCallsPerTick`, `maxActsPerTick`; `cell_status` reports `modelCallsToday` and `modelDailyCalls` in the operator's budget. `deployments/loop-d/` is the run's working directory (ignored); `deployments/loop-d.local.json` its evidence; `deployments/loop-d.local.example.json` one run kept.
- **Tests.** `test/model.test.ts` (6: the stub's order and stops, the over-budget proposal once, settlement and withdrawal, failed and refused tenders left alone, the Anthropic adapter against a stand-in API — headers, tools, tool results, a retry, errors without the key — and each Loop D verdict's failure on a synthetic evidence file), `test/loop-d.test.ts` (anvil; the 3c gate: the whole run with the stub, every verdict Pass, the model-agnostic row NotTested). 82 unit tests with anvil present. ## 0.6.0-alpha.3 — 2026-11-02 (Phase 3b: MCP and HTTP)

The catalog of 3a-2 gets its second and third entrances: an MCP server (stdio for local clients, Streamable HTTP for remote ones, both protocol eras) and an HTTP API, with API keys for the acts the public may not make, the npm package prepared for publication, and a client test suite on anvil as the gate. docs/mcp.md.

- **The MCP server** (`src/mcp/server.ts`; `@modelcontextprotocol/server` 2.4.0): one `McpServer` per caller, built from `catalog.list(caller)`. A read is one tool; a write capability is `<name>` (act; `destructiveHint` except for `tender_precheck` and `aid_heartbeat`), `<name>_simulate` (every check and a dry run, a decision record, nothing sent) and `<name>_build` (the calls for the caller's own account; not for `tender_precheck` or `skill_run`), each offered only at the caller's level. Results are `structuredContent` under the capability's output schema (a non-object read output under `result`); a refused act is `isError: true` with `refused at <gate>: <reason>` and `{ok: false, gate, reason, decisionId, jobId}`; `tender_precheck` answers `{eligible: false, gate, reason, decisionId}` as an ordinary result. Resources `foga://world`, `foga://cell/status`, `foga://policy`, `foga://spec/foga-cell-v1`, `foga://docs/compatibility-matrix`; prompt `take-tender`. Admin capabilities are not offered.
- **Both protocol eras, both transports.** The 2026-07-28 revision (`server/discover`, per-request `_meta`, no session) is the main path; 2025-era clients (`initialize`, 2025-11-25 and earlier) are served by the SDK's stateless compatibility layer. `foga node mcp --config <cfg>` (`foga mcp` is the same) serves stdio: the operator with `FOGA_OPERATOR_KEY[_FILE]`, otherwise a local user at build level with the operator's view; logs on stderr, protocol on stdout; a mixed environment is refused before anything is read.
- **The HTTP entrance** (`src/http/server.ts`, `node:http`): `/mcp` over Streamable HTTP (the SDK's web-standard handler behind a small bridge; the caller rides in `authInfo`), `GET /healthz`, `GET /`, `GET /api/capabilities`, `POST /api/<capability>[?mode=]`, `GET /api/<read>?…`, `GET /api/jobs/<id>`, `/api/operations/<id>`, `/api/decisions`; `/.well-known/*` and `/documents/*` answer `not published yet` until 3d. Without a credential the caller is the public (build level, public data); `Authorization: Bearer <key>` is the grant the key names. 401 unknown credential, 403 permission (capability, mode, Host, Origin), 400 input, 404, 405, 413 body cap, 415 content type, 429 rate; a business refusal is `200 {ok: false, gate, reason, decisionId}`. The edge: loopback listener by default (`runtime.http.listen`), `allowedHosts`, `allowedOrigins` (no CORS headers), `X-Forwarded-For` trusted from the loopback alone, a token bucket per address, request and header timeouts, `cache-control: no-store`.
- **API keys** (`foga node key new --config <cfg> --id <id> [--level] [--visibility] [--note]`): `foga.<id>.<24 random bytes>`, printed once; the config's new `access.keys` block holds `{id, sha256, level, visibility, note}`; the hash is compared in constant time; nothing of a key reaches a log. `foga node serve --config <cfg> [--listen] [--no-watch]` runs the server with the watchers beside it when it holds the operator key.
- **Configuration.** `runtime.http` (`listen`, `allowedOrigins`, `allowedHosts`, `publicUrl`, `rateLimitPerMinute`, `maxBodyBytes`) and `access.keys` added to `foga.cell-config/1`; both default, so a 3a-2 config loads unchanged. `spec_read` (read, public) serves the FOGA-Cell-v1 specification, the cell's policy, the compatibility matrix and the configuration schema from inside the package: 29 capabilities. `deployments/sepolia.cell.example.json`: the OG instance's identity line (agent 11255, account `0x09F3…2D75`) as a read-only configuration on the Sepolia world.
- **Two corrections found by the gate.** The request hash that binds a job (`hashInput`) excludes the idempotency key `jobId`: a request first made under a derived job id and then repeated naming that id is the same request (idempotent), while the same id with another input is still a conflict. `foga cell init` adopts the FOGA-Cell-v1 specification the owner already published (the registry derives the id from publisher and salt) instead of failing with `SpecificationExists` on the owner's second cell; a node no longer refuses a revision-1 account outright but refuses to hold the operator key on one, so the OG instance's revision-1 body can be served read-only.
- **Package.** `package.json`: version, `mcpName: "io.github.garyyang-finchip/foga"`, `keywords`, `engines.node >=22.13` (`node:sqlite` without a flag), `docs/` and `server.json` in `files`; `server.json` is the MCP registry manifest (the npm package as a stdio server, `https://foga.finchip.ai/mcp` as the remote; schema 2025-12-11). `scripts/pack-smoke.mjs <rpc> <world.json>`: `npm pack`, a clean install of the tarball, and the packaged CLI alone — help, catalog, schema, a cell born, `foga node mcp` without a key driven over stdio by a raw 2025-era client (stdout protocol-only, the keyless tool set, `cell_status`, resources, `spec_read` of the matrix, no key-shaped value on stderr) — run by CI after the genesis on the same anvil (the step turns a failure's tail into an annotation readable without the logs). Publication to npm and the registry is 3d.
- **Tests.** `test/mcp.test.ts` (anvil; the 3b gate) on a cell born by `test/helpers/anvil-cell.ts`: the health and front pages; the edge (401 for a bad, a foreign-id and a non-Bearer credential, 403 for a foreign Origin and Host, 413, 415, 400, 404, 405); the JSON API as the public and as a key holder; a client pinned to 2026-07-28 as the public (11 tools and their annotations, `cell_status`, `tender_precheck_simulate` → `eligible: false` at `skill` and eligible, no act offered, resources, prompt) and as the key holder (36 tools; case a from `tender_precheck` through `skill_run`, `tender_submit`, the same job answered once, `conflict`, `tender_settle` with the reward on the account, `credit_withdraw`; its own job, operation and decisions; `tender_mint_build` for a third party); a legacy and an auto-negotiating client; the rate limiter; stdio without a key (31 tools, `evidence_export`) and with the operator key (40 tools, no admin). `test/node-cli.test.ts` gains the owner's second cell adopting the published specification; `test/catalog.test.ts` the request hash without `jobId`. 75 unit tests with anvil present.

## 0.6.0-alpha.2 — 2026-11-02 (Phase 3a-2: the capability catalog and the node)

The kernel of 3a-1 becomes a node other agents can call: a catalog of capabilities that is the one authorization boundary, a policy engine applying the cell's own rules, decision records for every attempt to act, and the runtime of a cell that lives outside the genesis. The CLI is the first entrance; MCP and HTTP (3b) and A2A (3d) are further entrances onto the same catalog. docs/node.md.

- **The capability catalog** (`src/tools/`): 28 capabilities on the Loop D path (reads `world_describe`, `identity_resolve`, `tender_list`, `tender_inspect`, `skill_list`, `skill_inspect`, `cell_status`, `operation_status`, `job_status`, `operation_list`, `decision_list`, `evidence_export`, `kya_check`, `safety_status`; acts `tender_precheck`, `skill_run`, `tender_submit`, `tender_settle`, `credit_withdraw`, `tender_mint`, `tender_fund`, `skill_mint`, `aid_heartbeat`; admin `operator_rotate`, `guardian_suspend`, `guardian_resume`, `binding_present`, `identity_transfer`). Each declares its action (read / build / act / admin), the visibility of its data (public / caller / operator) and whose act it is (none / the cell / the account a build is for), with zod input and output schemas published as JSON Schema 2020-12. Three execution modes for a write: `simulate` (every check and a dry run, a decision record, nothing sent), `build` (the calls for someone else's account, `as`), `act`.
- **Three checks, in the catalog, for every act** (`Catalog.invoke`): call permission (visibility, level for the mode, the signer's key present for an admin act), business authorization (the capability's plan judged by the policy engine, `src/node/policy.ts` — gates `safety`, `skill`, `policy`, `verifier` — and the catalog's `budget` gate over the last 24 hours of value and fees plus open reservations, the per-operation cap and the concurrent commitments), wallet permission (the first step simulated from its signer; the account decides again on chain). The first refusal ends the attempt; an act that passed is recorded as allowed before anything is sent, and a failure after that is a second record at gate `execution`, naming the operation.
- **Decision records** (`decisions` table; `OperationStore.decide`, `decisions`, and the store summary): `{entrance, caller, capability, mode, inputHash, verdict, gate, reason, jobId, operationId, model}` for every act attempt in every mode; reads leave none; a model's words never enter one, only their hashes. `decision_list` for a caller's own, `evidence_export` (`foga.node-evidence/1`) for the operator's whole view.
- **Jobs and operations.** A job is created only once every gate has passed, so a refusal leaves a decision and nothing else; a job's id is the caller's `jobId` or one derived from the semantic input — a tender's n-th completion by the cell is `tender:<tokenId>:c<n>`, so a second legitimate completion is another job; the same job is answered from the store (`idempotent`), a failed job answers with its failure, the same job under another request is a `conflict`; an interrupted job continues. `tender_precheck` is ephemeral: a decision, no job. Operation keys are `job:<jobId>:<step>`, each bound to the request's hash, the capability, the caller and the cell (3a-1's bindings). `Cell.execute` and `Cell.admin` take a binding; `OperationStore.budgetBooks` keeps value and fees apart; `countJobs` counts the running commitments.
- **The cell configuration** (`src/node/config.ts`, schema `foga.cell-config/1`): identity, presence, skills (held and offered, the packages and input directories), policy (budget and tender rules), runtime; validated with zod, paths resolved against the file, written back by `init`, `migrate` and `skill_mint`.
- **The node** (`src/node/node.ts`): the kernel opened on the cell's world and store with only the keys this process holds (the operator's for a node, the owner's or the guardian's for a one-shot admin command), the cell handle, the policy's view of the store. It refuses a revision-1 account, an account whose operator or owner differs from the config, a key that disagrees with the config, and a store that belongs to another cell.
- **Birth and migration.** `foga cell init` is T1 for one cell from its config (the owner's act; the specification published when the config names none; the operator's allow-list from the standalone scope groups; every step a keyed operation, so it resumes and replays); `foga cell migrate` is T9 for one cell (a new revision-2 account with a fresh operator if given, the agent moved as the owner's act, the takeover and retirement, record, document and unit, the skills following with their records recommitted, the old balance swept). `src/node/init.ts`, `src/node/migrate.ts`.
- **The watchers** (`src/node/watchers.ts`; `foga node tick`, `foga node watch`): heartbeat when under half the window is left, discovery of open tenders (`tender-discovered`), settlement of pending submissions whose answer a run holds and withdrawal of credit, a `safety-changed` entry when the verdict changes — through the catalog like any caller, in a node environment (the operator key alone; an environment that also holds the owner's or guardian's key is refused: `FOGA_OWNER_KEY[_FILE]` and `FOGA_GUARDIAN_KEY[_FILE]` join the forbidden list). `loadRoleKey` reads those two for the CLI's one-shot commands.
- **The CLI** (`src/cli-cell.ts`): `foga cell list | schema | new | init | migrate | status | <capability> [--mode] [--<field> <value>] [--json]`, `foga cell owner … | guardian …`, `foga node tick | watch`; refusals exit 2 with `{ok: false, gate, reason, decisionId}`; `--caller`/`--level` call as another caller would. `inputDir` added to the skills block; an inline document (a `data:` URI in a task's input) is written beside the cell's store and read from there.
- **Tests.** `test/node-cli.test.ts` (anvil; the 3a-2 gate: a world, a cell born by `foga cell init` without the genesis, standing from the issuer, two skills minted, the seven Loop D cases a–g through the CLI — a and b taken and settled, c `skill`, d `policy`, e `verifier`, f `safety` then allowed after the resume, g `budget` — idempotency, conflict, build mode, the acceptance matrix read from the records and the chain, `foga node tick` in a clean and a mixed environment, the migration to a new account with a fresh operator), `test/policy.test.ts` (6), `test/catalog.test.ts` (4), `test/node-config.test.ts` (2). 74 unit tests with anvil present (73 without), the Foundry suite and the genesis unchanged and green.
- Dependencies: `zod` 4.6.7 (schemas and their JSON Schema). The kernel's own tree stays at ethers.
- Documentation: docs/node.md (new), docs/kernel.md (the store row, jobs, the node's keys), docs/design-memo.md (section 9: 3a-2), README (status, layout, commands).

## 0.6.0-alpha.1 — 2026-11-02 (Phase 3a-1: the kernel hardened for a public node)

Phase 3 reuses the kernel rather than building a node beside it; this slice gives it the permission, concurrency and recovery semantics a public service needs, all of them from the advisor's review of 0.5.0 (docs/design-memo.md, section 9). Nothing in it changes what the genesis proves; the scenario gains six operations that open each cell's operator scope.

- **FogaCellAccount revision 2** (`ACCOUNT_VERSION = 2`; the bundle is rebuilt, hash `0xb09770ec…`; only `foga:FogaCellAccount`'s code changed — the predicate adapter's `immutableReferences` carry renumbered AST ids from the same compilation unit, its bytecode is byte-identical). The operator may call only the (target, selector) pairs the owner allow-listed — `setOperatorAllowed`, `setOperatorAllowedBatch`, `operatorAllowed`, `OperatorAllowedSet`; a call outside the list reverts with `OperatorNotAllowed` — and never an asset-moving selector (`transfer`, `transferFrom`, the ERC-721 and ERC-1155 `safeTransferFrom`s, `safeBatchTransferFrom`, `approve`, `setApprovalForAll`, `increaseAllowance`, `permit`: `OperatorAssetSelector`, also when the owner tries to allow-list one). ERC-1271 signatures by the operator are off by default (`setOperatorMaySign`, `operatorMaySign`, `OperatorSigningSet`) and, when on, require the safety gate to be satisfied, not just the operator unexpired. The owner's calls are unchanged. 17 Foundry tests (two new, one extended). docs/cell-account.md. The 0.5.0 cells on Sepolia are revision-1 accounts; the OG instance moves to a revision-2 account in 3d.
- **The genesis opens the scope it uses.** `src/genesis/operator-scope.ts` names the scope in groups after what a cell does (identity, standing, skills-provider, labour, demander, organization-member, organization-coordinator, service-provider, service-client); T1 sets each cell's list in one batch after `setOperator` (`T1.<X>.scope`, recorded as a fact), T4 opens the swarm's decision adapter and account to B's operator when they exist (`T4.B.scope.*`), T9 sets A-prime's (`T9.Aprime.scope`), and A's identity and skill move to A-prime signed by A's owner, which is the only key the account lets move an asset. The lists were taken from a recording of every `execute` the 0.5.0 genesis made through an operator and are kept honest by the run itself, which fails on a call outside them. Scenario version 5: 193 operations on anvil (187 before), 201 in the attach rehearsal (195), 166 and 171 checks as before; the ERC-8004 selectors come from the module ABI so an attached official registry resolves too.
- **Transaction manager.** The number of fee replacements is counted on the operation's row and persisted (`replacements`): the old loop recursed into the wait and started the count again on every timeout, so the "three replacements" limit never held across a resumed run. A fee cap (`maxFeePerGasCap`, per manager or per request) clamps the first send (`fee-capped`) and refuses a replacement that would pass it (`replace-capped`); at the limit or the cap the pending transaction is waited for as it is (`replace-limit`), and the row stays `sent` for the next run. One signer's operations now run one at a time, in order, whoever asks concurrently; other signers run beside it. A key is bound to the canonical hash of its request (`OpBinding`): the same key with another request is `OperationConflict` before the chain is touched, a key claimed without a hash takes the first it is asked with. A failed operation answers with its failure on every later send (`replayed-failure`) until retried explicitly (`retryFailed`: the genesis driver retries, a public caller does not; `retry` puts the row back to `prepared` and keeps the fee the reverted attempt cost); the hashes of a retried attempt are not waited for again. Rows record the value a transaction carries and the fees paid (cumulative over attempts); `budgetUse(signer, since)` gives what settled operations spent and what open ones reserve. An RPC failure while waiting leaves the row `sent`.
- **Store.** New columns on `ops` (replacements, request hash, capability, caller, cell, value, fee cap, gas cost; an older store gains them on open) and a `jobs` table (`createJob`, `updateJob`, `getJob`, `jobs(caller)`: the business unit a caller asks for, with its input hash, state, result and the operations it made; the same id with another input is a conflict). `transaction(fn)` for a claim and its reservation; nested calls join the outer transaction. The kernel checks the store's world id and chain id against the world file, not just block 0, and completes an older store's identity on its first open.
- **Keys.** A node holds one key: `src/node/keys.ts` loads it from `FOGA_OPERATOR_KEY_FILE` (a regular file owned by the node's user, mode 0600 or tighter) or `FOGA_OPERATOR_KEY`, exactly one of the two, and refuses to start when the environment also carries `FOGA_MNEMONIC`, `FOGA_MNEMONIC_FILE`, `FOGA_DEPLOYER_PK` or any `FOGA_KEY_<ROLE>` — the refusal names the variables, never their values. `foga keys export --role <role> [--out <file>]` writes one role's key to a 0600 file from the operator's phrase; `foga keys check` reads the current environment as a node would. The genesis still derives its twelve roles as before.
- **Skill worker.** `src/genesis/probe-worker.ts` is replaced by `src/genesis/skill-worker.ts`, one worker for both executors: `finch-extract-verify`'s extraction now runs out of process too (T5 and T7), a document is accepted only inside the input directory and a fields file only inside the skills directory (real paths). The worker's environment is `PATH` alone (no inherited `NODE_OPTIONS`), its heap is capped at 512 MB, its output at 1 MiB, and when the parent is not under the development loader it runs under Node's permission model with read access to the directories the job names (verified from the compiled build: a read outside them is `ERR_ACCESS_DENIED`).
- **Tests.** `test/mock-chain.ts`, an in-process JSON-RPC chain (pool, mining on command, replacement pricing, reverts, flaky receipt lookups, a consumed nonce, a reset block 0); `test/tx-semantics.test.ts` (12 tests: the replacement limit across a restart, the same key under two requests, a key gaining its binding, the reverted operation and its explicit retry, the estimate that reverts, one signer's queue beside another signer's, a failure not blocking the queue, the fee cap at the first send and at a replacement, the failing receipt lookup, the forgotten transaction re-sent, the consumed nonce left ambiguous, one replacement completing the operation); `test/store.test.ts` (+5: bindings, replacements and cumulative fees, budget use, jobs, the migration of a 0.5.0 store); `test/keys.test.ts` (3); `test/kernel-open.test.ts` (1). 61 unit tests (one of them the anvil replacement test, skipped where anvil is not installed), the Foundry suite, the genesis T0–T9 on anvil with the injected crash and its resume, the replay and the attach rehearsal all green.
- CI: `actions/cache` moved from v4 to v5.
- Correction to the 0.5.0-alpha.9 entry below: its last sentence said anvil hid the seeded-pin defect; it did not — the CI run of alpha.8 failed on the resumed genesis for that reason. The sentence is withdrawn.

## 0.5.0-alpha.9 — 2026-11-01

- Fix: the read pin is seeded with the chain's head when the kernel (or `foga world deploy`) opens. A replayed run sends nothing, so the only blocks the provider saw were those of the old receipts it read back, and the pin followed them: every check read the chain as it was at that step, not as it is now — `T2 A.document.prior` read the document before its own update and `T4 swarm.active` read the swarm before its conclusion, on every Sepolia replay, although both hold on chain (verified against an independent node). The alpha.8 diagnosis of stale nodes was wrong; the reads were at the right node and the wrong block. (A sentence that stood here, saying anvil hid the defect, was withdrawn in 0.6.0-alpha.1: the CI run of alpha.8 had failed on the resumed genesis for this very reason.)

## 0.5.0-alpha.8 — 2026-11-01

- `PinnedProvider` no longer falls back to a read at "latest": the Sepolia replay showed that the node refusing an explicit block can be the one hours behind, and its stale answers failed `T4 swarm.active` (ACTIVE after the conclusion) and `T2 A.document.prior` (the digest before the update) although both hold on chain. Retries now last up to 60 s; then the endpoint's head is sampled and a pin that came from a node ahead of the rest is lowered to it, once; otherwise the error is raised with the node's own words and the run stops, to be resumed from its store. The provider test covers both paths.
- Replay guards: A's liveness checks of T1 and T7 (`A.aid.active`, `A.aid.backing`, `A.ard.backed`, `anchor.active.gate`, `anchor.backing.active`) are also superseded by `T9.A.8004.transfer`, the first operation that changes A's anchor state, not only by the retirement; a run resumed between the two read them as failed.

## 0.5.0-alpha.5 — 2026-11-01

## 0.5.0-alpha.4 — 2026-11-01
